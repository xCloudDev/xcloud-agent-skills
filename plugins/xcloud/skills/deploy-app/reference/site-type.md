# `nodejs` vs `lovable`

`lovable` is not a distinct deployment engine — it is `nodejs` with the
xCloud-provisioned database suppressed. The only differences: no
`DatabaseProvider` is provisioned, and no database name/user/prefix are
generated for the site.

## Rule

Use `site_type: "nodejs"` unless **both** are true:

- the project is Lovable-origin (a Vite/React app generated by Lovable, most
  commonly using Supabase for its backend), **and**
- it needs no xCloud-provisioned database.

Otherwise use `nodejs`. In particular:

- A Lovable-origin app that *does* want an xCloud-managed database → `nodejs`.
- A hand-written Node app with no database → still `nodejs`; `lovable` is for
  Lovable-origin projects specifically, not "any database-less Node app."

## What this means in practice

- Let `git_detect` pick the site type from the repository; only override to
  `lovable` when the user confirms the project is Lovable-origin and has no
  database requirement.
- A Dockerfile present in a Lovable repo, or an external Supabase
  configuration, does **not** by itself force a Docker deployment — see the
  "What this skill does NOT do (yet)" section in `SKILL.md` for when Docker
  actually becomes necessary (multiple services, workers, self-hosted
  dependencies the native runtime can't express).
